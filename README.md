# Cadence

**Studio-grade short-form video, from one raw take.**

Analyze a reference video's aesthetic and pacing → record raw A-roll once →
the engine removes silence, filler words, and bad takes, then stitches a premium
**1080×1920 / 60fps** vertical video that matches the reference's style.

</div>

---

## What this is

A production, cross-platform short-form video automation system in two parts:

| Part | Path | Status |
|---|---|---|
| **Engine** — the video-processing brain (Python + FFmpeg 8.x) | [`engine/`](engine) | ✅ **Built & fully tested** (73 tests, real renders + real ASR, adversarially reviewed) |
| **Web app** — multi-tenant SaaS people sign up for (Next.js + Supabase) | [`web/`](web) | ✅ **Built & verified locally** (browser E2E + RLS isolation + backend smoke all pass) |
| **Worker** — render job processor wrapping the engine | [`worker/`](worker) | ✅ **Built & verified** (Supabase queue → FFmpeg render) |
| **Mobile app** — Flutter capture/control/preview client (Windows + Android) | [`app/`](app) | 🧩 **Architecturally-complete scaffold** (not device-tested in this env) |

### Sign-up-and-use SaaS (`web/` + `worker/`)
People sign up (email/Google), create a project, upload a reference + record/upload a clip,
customize, and **Generate** — the worker renders a premium vertical video and streams it back.
Verified end-to-end locally: a Playwright browser test (signup → render → result), a
cross-tenant **RLS isolation** test (6/6 — no user can touch another's data), and a backend
pipeline smoke test all pass. Server-side monthly render quotas. See [`web/README.md`](web/README.md) to run it.

> The split is deliberate and matches the research-validated architecture: **Python does
> all heavy analysis/render; Flutter is the capture + control + preview surface**, talking
> to the engine over a localhost HTTP sidecar. This box had Python + a full FFmpeg 8.1
> (NVENC/CUDA/whisper/libass) but no Flutter SDK or Galaxy S25 Ultra, so the engine is
> verified end-to-end here and the app ships as a real, build-ready scaffold.

## The pipeline (spec §1)

1. **Analyze** — reference video → dominant palette (K-means) + exposure, cut/transition
   detection & type classification, caption-zone mapping, and a pacing fingerprint.
2. **Configure** — a persistent brand board (logos/watermarks, palettes, fonts, caption styling).
3. **Capture & Clean** — record continuously through mistakes; the engine strips silence
   (RMS + word-gap), scrubs fillers (`um/uh/…`), and removes bad takes (keep the last good one).
4. **Synthesize** — stitch the cleaned A-roll to match the reference: trim/concat cuts,
   smart punch-in zoom to mask jump-cuts, reference-derived color grade, animated captions,
   brand watermark → a rendered MP4.

## Proof it works (generated by `engine/scripts/demo_pipeline.py`)

```
ANALYSIS  palette=[#1FC02E,#DE301F,#1F3EDE,…]  transitions=[(2.0,hard_cut),(4.0,hard_cut)]
          text overlays=[(0.4,1.8,bottom),(4.2,5.6,top)]  cut_density=20/min
CLEAN     source=6.00s → output=4.30s   (2 silence spans removed)
RENDER    1080x1920 @ 60fps  encoder=libx264 (NVENC smoke-tested, SW fallback)
```
Real-speech ASR run (`engine/scripts/verify_asr.py`, faster-whisper): a false-start
*"um, this is a test … this is a test of the cleaning system"* is transcribed with word
timestamps and the **first take is detected and removed** automatically.

See [`engine/output/`](engine/output) for `final.mp4`, frame thumbnails, the generation
plan JSON, and the exact filtergraph.

## Quick start

```bash
# Engine
cd engine
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt && pip install -e .
pytest                                  # run the test suite
cadence serve                           # start the localhost sidecar :8765

# App (on a machine with the Flutter SDK)
cd ../app
flutter pub get
flutter run -d windows                  # or -d <android-device>
```
